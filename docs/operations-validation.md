# Unified operations acceptance — 2026-11-11

This report covers the SPEC-002 CLI and executable documentation on macOS ARM64,
Linux ARM64 and Linux AMD64. It is separate from the earlier configuration acceptance
reported in `config-validation.md`.

## Local coverage

The final suite passed 67 Python tests plus 9 mocked Terraform tests on all three platforms. It exercises
both providers, unchanged remote backend keys, explicit config/kubeconfig selection,
private artifacts, approved binary plans, configuration/source/dependency drift,
malformed manifests, interruption/resume, local locking, safe JSON errors and exact
destructive confirmation. Destroy is tested with simulated processes only. Standalone smoke tests now honor `IAC_CONFIG` and the selected kubeconfig; their configuration override and failure cleanup are covered with simulated cloud commands, without live cleanup in this session.

Five marked documentation commands execute without cloud credentials. Pipeline tests
also cover GPG roundtrips, altered ciphertext/manifests, invalid archive paths, protected
files, OIDC session preparation, fresh kubeconfig naming and missing approval gates.
`actionlint` validates both workflows. Both container architectures build with a non-root
runtime user and include GPG for the encryption tests.

## Live operations

The new CLI applied reviewed foundation plans and deployed the complete stack in each
cloud: AWS network (43 resources), EKS (63), Flux (1), platform resources (4); Azure AKS
(7), Flux (1), platform resources (3). Configurations and kubeconfigs are isolated per
backend destination. Local run logs and configuration snapshots remain private.

Azure passed control-plane, nodes, HelmRelease and metrics verification, and all three
post-deployment plans returned zero changes. A real Azure plan bundle was encrypted,
restored to its original path and applied without replanning; all three plans remained
no-ops. Fresh kubeconfigs generated by the CI adapter accessed two Ready nodes in each
cloud without administrative credentials.

AWS passed verification with two Ready nodes, four healthy EKS add-ons, six Ready HelmReleases and working metrics. All four AWS post-deployment plans returned zero changes. Both bootstrap plans also returned zero changes. A subsequent Azure resume verified all three completed stages without repeating apply. A real resume using an older source fingerprint was rejected before any cloud mutation.

## Retention and pipeline limits

**Both clusters are retained at the owner's request.** No real destroy command was run
in this acceptance. The private inventory is `.iac/retained-infrastructure.json`; it lists
configurations and kubeconfig paths. Backend storage is also retained.

GitHub deployment has not been activated: environments, reviewer identities, private
runners and OIDC trusts are not configured. The environment gate rejected the absent
configuration in a real read-only GitHub check. The security scan found no secrets but
retains three infrastructure findings; see `pipeline.md`. No suppressions were added.
The CycloneDX SBOM records the dependencies discovered in the repository and does not
claim complete OS/container/Helm coverage. No commit or push was performed.
